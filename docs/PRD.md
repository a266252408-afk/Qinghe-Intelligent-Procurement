# 产品需求规格（PRD）— 园林工程智能采购助手

> **文档定位**：本文档是项目的"需求说明书"，定义"我们要做什么"。后续 `system-design.md`（系统架构）与 `docs/module-sdd/`（模块级 SDD）将基于本文档展开"怎么做"。
> **文档来源**：基于 `参考文件/项目功能和描述参考.md` 与 6 轮采访式需求采集整理而成。
> **版本**：v0.1（待 review 迭代）

## 1. 产品概述

### 1.1 一句话描述
面向园林工程采购场景的 AI 副驾驶式 Web 应用，通过对话式交互帮助采购员完成清单解析、询价单生成、报价比价、历史价格检索等工作，把采购员从重复文书劳动中解放出来。

### 1.2 产品定位
- **是"采购员的 AI 超级助手"，不是"自动采购机器人"**。
- 大模型核心作用：处理非结构化信息、辅助决策、自动化繁琐的沟通与文书工作。
- **设计理念**：AI 辅助，而非 AI 替代。AI 做识别/提取/标准化/初步建议；人做确认/修正/决策/谈判。

### 1.3 核心价值锚点
"为采购员每周节省 10+ 小时重复劳动"——通过自然语言降低使用门槛，通过非结构化信息处理解决传统软件无法覆盖的痛点。

## 2. 项目背景与定位

| 维度 | 决策 | 说明 |
|:----- |:----- |:----- |
| 项目性质 | 面试/求职作品 | 技术完整度与产品思维优先于商业落地，需能清晰展示大模型应用价值 |
| 商业模式 | MVP 不收费，预留商业化扩展接口 | 不实现付费/订阅逻辑，但用户与团队数据模型需为后续多租户订阅留扩展点 |
| 交付形态 | Web 应用优先，架构可扩展到小程序/IM 集成 | 前端技术选型需考虑后续多端复用 |
| 开发范式 | SDD 驱动 + 多 Agent 协作 + 骨架先行 | 先 SDD 文档后代码；先定接口骨架后补业务逻辑；工具模块遵循开闭原则 |
| 部署方式 | 提供 Docker Compose 一键运行（后端 + 前端），也支持本地直接运行 | 便于演示与环境复现 |

## 3. 目标用户与角色权限

### 3.1 目标用户画像
- **主用户：园林工程公司采购员**（1-3 年经验，熟悉苗木但不熟悉复杂软件操作，日常使用微信/Excel 沟通）。
- **次用户：采购主管**（管理 1-N 个采购员，需审批与团队看板）。

### 3.2 角色定义与权限矩阵

| 功能/权限 | 采购员 | 采购主管 |
|:--------- |:------:|:--------:|
| 创建采购单/上传清单 | ✅ | ✅ |
| 生成询价单/上传报价 | ✅ | ✅ |
| 查看比价分析 | ✅ | ✅ |
| 查询历史知识库 | ✅ | ✅ |
| 提交下单申请 | ✅ | ✅ |
| **审批下单申请** | ❌ | ✅ |
| **查看团队所有采购单** | 仅本人 | 全团队 |
| **团队看板与报表** | ❌ | ✅ |
| **团队成员管理** | ❌ | ✅ |
| **行业认知库维护** | 只读 | 可维护 |

### 3.3 团队模式与数据隔离
- 采用**团队模式**：一个团队内含 1 个主管 + N 个采购员。
- **团队内数据共享**：采购单、询价单、报价、供应商信息、长期记忆库对团队内可见。
- **团队间数据完全隔离**：跨团队不可见任何业务数据。
- **可溯源**：每一张采购单的每一项操作（创建/修改/审批/下单）必须记录操作人、时间戳，支持追溯。

### 3.4 默认设计（可调整）
- 一个用户可属于多个团队（如采购员 A 同时服务 B 团队），MVP 阶段先简化为"一个用户仅属于一个团队"，数据模型预留多对多扩展点。
- 主管即团队创建者，可邀请采购员加入（邀请码或邮箱注册绑定）。

## 4. 核心业务流程

### 4.1 六步采购流程（按项目管理）
每个采购任务必须挂载在一个**项目**下，独立走完整流程：

```
1. 清单解析 → 2. 询价生成 → 3. 报价解析 → 4. 智能比价 → 5. 下单审批 → 6. 收货对账
```

### 4.2 端到端流程（含主管审批）

```
[采购员] 创建采购单（挂项目下）
   ↓
[采购员] 上传清单（Excel/CSV/文本/图片可选）
   ↓
[AI]    智能清单解析 → 结构化预览
   ↓
[采购员] 确认/修正清单
   ↓
[AI]    生成询价单（选模板）→ 采购员下载导出，自行发给供应商
   ↓
[供应商] 按原方式回传报价（邮件/微信）
   ↓
[采购员] 上传报价文件
   ↓
[AI]    解析报价 → 智能比价（可视化图表 + AI 建议）
   ↓
[采购员] 选择供应商 → 提交下单申请
   ↓
[采购主管] 审批 → 通过/驳回（驳回需备注原因）
   ↓ 通过
[正式下单] → 系统记录成交价、供应商、付款条件等
   ↓
[采购员] 收货确认 / 对账结算
   ↓
[系统] 自动沉淀到长期记忆库
```

### 4.3 异常分支
- 主管**驳回**：采购员收到驳回原因，修改后可重新提交。
- 主管**长期未审批**：系统在采购员侧标注"待审批"状态，不做自动催办（MVP 简化）。
- 收货**部分到货**：MVP 不做部分收货，仅支持"全部到货确认"；扩展点预留。

## 5. 功能需求（FR）

### FR-1：项目与采购单管理
- 用户可创建项目（项目名称、负责人、预算、状态、备注）。
- 每个项目下可创建多张采购单。
- 采购单状态机：草稿 → 待审批 → 已通过 → 已下单 → 已收货 → 已对账 / 已驳回。
- 支持按项目、按状态、按时间筛选采购单。

### FR-2：智能清单解析器（P0，MVP 必须）
**输入支持**（分层）：
- **基础模式**：纯文本/对话输入、Excel/CSV 文件。
- **高阶模式（开关式接入）**：图片/扫描件多模态解析（GPT-4o/Claude 视觉能力）。默认关闭，用户在系统设置中开启。

**解析能力**：
- 多模态识别 + 语义理解 + 标准化：将"Φ12香樟"、"香樟胸径12"统一为 `{"species":"香樟", "spec":"胸径12cm", "quantity": 30, "unit":"株"}`。
- 容错：必填字段（species/spec/quantity）缺失时，标注"未提供"而非报错。
- 置信度：解析置信度 < 0.8 时，高亮不确定字段请求人工确认。

**输出**：结构化 JSON 采购清单 + 前端预览表格，用户可在线编辑修正后入库。

### FR-3：询价单生成（P1，MVP 必须）
**生成流程**：
1. 从当前对话/采购单上下文获取已确认的采购清单。
2. 展示预览（品名、规格、数量、单位、价格占位）。
3. 提供 2-4 个预设模板供选择（见默认设计）。
4. 用户确认后生成可下载文件（Excel 为主，后续可扩展 PDF）。
5. 自动记录本次询价内容到长期记忆库。

**MVP 范围**：仅生成下载，不集成邮件/IM 自动发送（用户自行发送）。

### FR-4：报价单解析（P2，MVP 包含）
**输入方式**：采购员手动上传供应商报价文件（Excel/CSV/文本）。
**解析字段**：供应商名称、品种、规格、单价、数量、总价、交货期、付款条件、有效期。
**缺失处理**：字段缺失时标注"未提供"，保留部分结果。
**输出**：结构化报价数据，与采购清单进行匹配比对。

### FR-5：智能比价分析（P2，MVP 包含）
**对比维度**：
- **核心维度**：单价、交货最短日期。
- **附加维度**：历史合作评分（来自长期记忆库）、付款条件。
- **可视化**：表格对比 + 柱状图（价格对比）+ 雷达图（多维度评分）。
- **AI 建议**：基于可配置权重生成自然语言推荐（如"建议选 A 供应商，价格最低且历史评分 4.5"）。

**权重配置**：默认 价格 40% / 历史 30% / 交货期 20% / 付款 10%，主管可在团队设置中调整权重。

### FR-6：历史价格知识库检索（P1，MVP 必须）
- 支持**自然语言检索**："去年 3 月买过 15cm 的香樟吗？多少钱？"
- 检索结果按相关度排序，展示历史记录明细。
- 趋势分析：对"品种-规格"组合生成近一年价格走势图（折线图）。
- 数据范围：仅查询本团队长期记忆库中的数据。

### FR-7：三层知识库管理（核心架构）
详细设计见第 6 章。三层：
- **行业认知库**（事实知识库，团队共享只读 + 主管可维护）
- **长期记忆库**（团队业务数据，团队内共享）
- **短期对话记忆库**（会话级，用户私有）

### FR-8：对话式交互与斜杠命令
- 类 ChatGPT 对话界面，支持流式输出。
- 多会话管理：每个会话可关联一个项目，会话列表展示在侧边栏。
- 会话内多轮上下文：保留完整对话历史，超出上下文窗口时滚动截断。
- **斜杠命令**（用户与 AI 协作沉淀数据的关键交互）：

| 命令 | 作用 |
|:----- |:----- |
| `/记录` 或 `/save` | AI 总结当前对话/任务关键信息，提取到长期记忆库（需人工确认） |
| `/总结` 或 `/summary` | 总结当前会话要点 |
| `/比价` 或 `/compare` | 触发当前采购单的比价分析 |
| `/询价` 或 `/inquiry` | 生成询价单 |
| `/历史` 或 `/history` | 检索历史价格 |
| `/帮助` 或 `/help` | 查看可用命令列表 |

### FR-9：团队与权限管理
- 团队创建者即主管，可邀请采购员加入。
- 角色与权限遵循 3.2 矩阵。
- 操作审计日志：记录关键操作（下单/审批/删除/修改采购单）的操作人、时间、变更内容。

### FR-10：用户登录与系统配置
- **登录即注册**：第一次输入用户名密码即注册（MVP 简化，无独立注册页）。
- **用户隔离**：每个用户数据独立，登录后需选择/创建团队。
- **会话管理**：JWT Token，过期重新登录。

> **说明**：MVP 阶段大模型 API Key 与地址由开发者直接在服务端环境变量中配置（作为应用大脑），**用户无需在界面上配置大模型**。这样降低用户使用门槛，也避免面试演示时暴露密钥。后续可扩展为用户自助配置（作为预留扩展点）。

## 6. 数据需求与知识库设计

### 6.1 三层知识库详细设计

#### 6.1.1 行业认知库（事实知识库）
**定位**：内置园林行业常识，让大模型回答有依据、减少幻觉，可辅助给出采购建议。

**初始化内容范围**（默认设计，可调整）：
- 苗木品种库：常见园林苗木标准中文名称（避免"樟树/香樟"歧义）。
- 规格术语表：胸径（DBH）、冠幅、株高、土球直径等术语定义与单位。
- 常见采购规则参考：如"胸径测量距地面 1.3m 处"等行业惯例。
- 市场行情参考（可选，需人工维护，标注更新日期）。

**积累方式**：主要支持上传文件（PDF/Word/Excel/文本）入库，自动向量化存储。
**权限**：团队内只读，主管可上传/更新/删除。

#### 6.1.2 长期记忆库（用户私有业务数据）
**定位**：团队日常采购业务数据的沉淀，支持后续检索与比价参考。

**数据内容**（三类）：
1. **采购清单记录**：品种、规格、数量、单位、采购日期、所属项目。
2. **报价与成交记录**：供应商名称、报价、最终成交价、付款条件、交货期、采购日期。
3. **供应商信息**：名称、联系人、联系方式、主营品类、历史合作评分、备注。

**积累方式**（三层）：
- **操作即记录（主要）**：每次询价/比价/下单自动入库相关数据。
- **斜杠命令主动提取**：用户输入 `/记录` → AI 总结提取关键信息 → 采购员确认 → 在线修改 → 确认无误后录入长期记忆库。
- **手动上传文件**（辅助）：批量上传历史采购 Excel 入库。

**权限**：团队内共享，团队间隔离。

#### 6.1.3 短期对话记忆库
**定位**：管理多会话与单会话内多轮上下文，保证对话连续性。

**设计**：
- 每个会话独立，可关联一个项目。
- 会话列表展示在侧边栏，支持切换/重命名/删除。
- 会话内保留完整多轮上下文，超出上下文窗口时按"保留首尾、压缩中段"策略滚动截断。

### 6.2 数据模型概览（核心实体）

```sql
-- 用户与团队
users(id, username, password_hash, display_name, created_at)
teams(id, name, creator_id, created_at)
team_members(team_id, user_id, role)  -- role: owner/member

-- 项目与采购单
projects(id, team_id, name, owner_id, budget, status, created_at)
purchase_orders(id, project_id, creator_id, status, total_amount, created_at, updated_at)
purchase_items(id, order_id, species, spec, quantity, unit, unit_price, total_price)

-- 询价与报价
inquiry_sheets(id, order_id, template_id, file_path, created_at)
quotes(id, order_id, supplier_id, file_path, parsed_data_json, created_at)
quote_items(id, quote_id, species, spec, unit_price, quantity, total_price,
            delivery_days, payment_terms, valid_until)

-- 供应商
suppliers(id, team_id, name, contact, phone, main_category, rating, remark)

-- 审批
approval_records(id, order_id, approver_id, decision, reason, created_at)

-- 知识库
industry_knowledge(id, team_id, source_file, content, vector_id, updated_at)
conversation_sessions(id, user_id, project_id, title, created_at)
messages(id, session_id, role, content, metadata_json, created_at)

-- 审计日志
audit_logs(id, team_id, user_id, action, target_type, target_id, diff_json, created_at)
```

### 6.3 数据隔离规则
- 所有业务表通过 `team_id` 或其父实体（如 `purchase_orders.project_id → projects.team_id`）实现团队隔离。
- 查询时必须带 `team_id` 过滤，由数据访问层统一拦截（禁止业务层裸 SQL 绕过）。
- 用户表与团队解耦，支持后续多团队扩展。

## 7. 系统交互逻辑

### 7.1 主界面布局
**对话为中心 + 侧边栏项目/会话**（类 ChatGPT 布局）：
- **左侧栏**：项目列表 → 会话列表（当前项目下）。
- **主对话区**：当前会话的消息流 + 底部输入框（支持斜杠命令、文件上传）。
- **顶部**：快捷功能入口（新建采购单、比价、生成询价单、知识库检索）。
- **右侧抽屉（可选）**：展示当前任务的结构化结果（解析预览/比价表/询价单预览）。

### 7.2 关键交互流程示例

**示例：清单解析**
```
用户上传 Excel → AI 解析 → 右侧抽屉展示结构化预览表格
  → 不确定字段高亮 → 用户修正 → 确认入库 → 关联当前采购单
```

**示例：斜杠命令记录**
```
用户输入 "/记录" → AI 提取当前会话关键信息（品种/规格/价格/供应商）
  → 弹出确认编辑框 → 用户在线修改 → 确认 → 写入长期记忆库
```

### 7.3 异常处理与置信度策略

| 场景 | 策略 |
|:----- |:----- |
| 解析置信度 < 0.8 | 高亮不确定字段，请求人工确认后再入库 |
| 必填字段缺失 | 标注"未提供"，保留部分结果，不报错 |
| 文件格式不支持 | 友好提示支持的格式列表 |
| 文件超 5MB | 提示"文件过大，请压缩或拆分后上传" |
| 大模型 API 不可用 | 降级为模板方案或提示用户检查配置，标注 `source: "template"` |
| 斜杠命令意图不明确 | AI 反问澄清，不擅自执行 |

### 7.4 默认设计（可调整）
- **询价单模板**：默认提供 4 个——标准询价单、简版询价单、含交货期要求版、绿化工程量清单版。前 3 个字段含：供应商名称、询价日期、有效期、品名、规格、数量、单位、备注、交货期要求、付款条件要求；绿化工程量清单版沿用《花箱绿化工程量清单》原表版式，表头“项目名称”自动带入采购单所属项目名称。
- **比价可视化**：表格 + 柱状图（价格对比）+ 雷达图（多维度评分），使用 Chart.js 或 ECharts。
- **行业认知库初始内容**：由项目方在初始化时提供一份基础苗木知识文件，后续主管可上传补充。

## 8. 非功能需求（NFR）

### NFR-1：性能
- 对话首字响应 < 2 秒（流式输出）。
- 文件解析 < 10 秒（单文件 < 5MB）。
- 比价报告生成 < 30 秒（含可视化图表）。
- 支持并发 10 用户（面试作品级别）。

### NFR-2：安全性
- 账号密码登录 + JWT 会话。
- 密码 bcrypt 哈希存储，禁止明文。
- API Key 不硬编码，从环境变量读取。
- 用户输入做注入防护（SQL 注入、Prompt 注入基础防护）。
- 团队间数据隔离（数据访问层强制 team_id 过滤）。
- 操作审计日志保留至少 90 天。

### NFR-3：可维护性
- 遵循 SDD 驱动开发，模块单一职责。
- 工具模块遵循**开闭原则**：新增工具只需注册，不改现有代码。
- 所有模块间通信使用 Pydantic 模型，禁止裸 dict 传递。
- 代码覆盖率：核心模块 100%，整体 ≥ 80%。
- 中文注释与文档；函数不超过 50 行。

### NFR-4：可扩展性（预留扩展点）
- **大模型供应商可配置**（OpenAI 兼容接口，支持切换 DeepSeek/通义/智谱等，开发者服务端配置）。
- **用户自助配置大模型**：MVP 不开放，预留为后续扩展（让用户在设置页填自己的 Key）。
- 多模态解析作为开关式高阶能力。
- 多团队/多角色扩展（数据模型已预留）。
- 后续可扩展：邮件/IM 自动发送询价单、供应商在线填报入口、移动端小程序。

### NFR-5：部署
- 云服务器部署（阿里云/腾讯云）。
- 提供 Docker Compose 一键运行，便于演示与环境复现。
- 前后端分离，API 可独立测试。

### NFR-6：合规
- 大模型 API Key 与用户业务数据均不外泄。
- 长期记忆库数据归团队所有，删除团队时数据级联清除。

## 9. 验收标准（AC）

### AC-1：登录与配置
- 首次输入用户名密码 → 自动注册并登录，跳转团队选择页。
- 创建团队后 → 直接进入主界面（无需配置大模型，由开发者服务端预置）。
- JWT 过期后 → 跳回登录页。

### AC-2：清单解析（P0）
- 上传一份含"品种/规格/数量"列的 Excel → 10 秒内返回结构化预览。
- 输入"香樟胸径12cm×30, 桂花8cm×20" → 解析为 2 行结构化清单。
- 上传含不确定字段的清单 → 不确定字段高亮，提示确认。
- 用户修正后 → 入库并关联到当前采购单。

### AC-3：询价单生成（P1）
- 在已确认清单的采购单中触发"生成询价单" → 展示预览 + 模板选择。
- 选择模板后 → 生成 Excel 文件供下载。
- 询价内容自动记录到长期记忆库。

### AC-4：历史检索（P1）
- 输入"去年买过香樟12cm吗" → 返回匹配的历史记录列表（按相关度排序）。
- 输入"香樟12cm 价格趋势" → 生成近一年价格折线图。

### AC-5：报价解析与比价（P2）
- 上传 2 份不同供应商报价 Excel → 解析为统一结构。
- 触发比价 → 展示表格 + 柱状图 + 雷达图 + AI 建议（含权重说明）。
- AI 建议中明确标注"建议选 X，理由：..."。

### AC-6：审批流
- 采购员提交下单申请 → 采购主管侧出现"待审批"标记。
- 主管通过 → 采购单状态变为"已通过 → 已下单"，记录成交信息。
- 主管驳回（填原因）→ 采购员侧显示驳回原因，可修改重提。

### AC-7：知识库
- 主管上传一份苗木知识 PDF → 入库成功 → 采购员询问相关问题时 AI 能引用回答。
- 输入 `/记录` → AI 提取信息 → 弹出确认编辑框 → 修改后确认 → 长期记忆库新增一条记录。

### AC-8：接口规范
- 所有 API 返回统一格式：`{"code": 0, "msg": "ok", "data": {...}}`。
- 错误返回：`{"code": 非0, "msg": "错误描述", "data": null}`。
- 流式对话接口使用 SSE 或 WebSocket。

### AC-9：数据隔离
- A 团队采购员查询历史 → 仅返回 A 团队数据，B 团队数据不可见。
- 每条采购单可追溯到创建人、审批人、操作时间。

## 10. 默认设计与扩展点汇总

### 10.1 默认设计决策（标注"可调整"，便于 review）
| 项 | 默认决策 | 理由 |
|:--- |:--- |:--- |
| 用户-团队关系 | 一对一 | MVP 简化，数据模型预留多对多 |
| 询价单模板数 | 4 个（标准/简版/含交货期/绿化工程量清单） | 覆盖常见场景与项目原表格式 |
| 比价权重默认值 | 价格40%/历史30%/交货期20%/付款10% | 参考文件建议，主管可调 |
| 行业认知库初始内容 | 项目方提供一份基础苗木知识文件 | 减少冷启动空白 |
| 部分收货 | 不支持，仅全部到货确认 | MVP 简化 |
| 自动催办 | 不做 | MVP 简化 |
| 询价单自动发送 | 不做，仅生成下载 | 用户自行发送 |
| 大模型默认 | OpenAI 兼容（聚合中转或自选供应商） | 由技术实现决定，文档不约束 |
| 图表库 | Chart.js 或 ECharts | 由技术实现决定 |

### 10.2 预留扩展点
- **多模态解析开关**：图片/扫描件解析作为高阶能力，默认关闭。
- **大模型可配置切换**：抽象模型层，运行时切换供应商。
- **多团队/多角色**：数据模型已预留，后续支持复杂组织架构。
- **询价单自动发送**：预留邮件/IM 集成接口。
- **供应商在线填报**：预留供应商侧轻量 Web 入口。
- **移动端**：前端架构考虑后续小程序/IM 集成复用。
- **向量库升级**：SQLite 存结构化数据 + Chroma 存向量，数据量增长后平滑迁移到 Qdrant。
